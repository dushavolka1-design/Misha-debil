# Промпты исправления «Анализатора документов РФ»

Выполнять строго по порядку в существующем репозитории:

`C:\Users\GariPotov1\Projects\document-analyzer-rf`

Каждый промпт — отдельная задача Cursor. Не передавать все промпты одновременно. После каждого этапа проверить приложение вручную и автоматическими тестами.

## Подтверждённые проблемы текущей версии

- На лендинге образуется большое пустое поле: `.dar-hero` имеет `min-height: min(92vh, 820px)` и `align-items: end`.
- В sidebar выведено десять равноправных пунктов: «Обзор», «Загрузка», «Очередь», «Отчёт», «Сравнение», «Мастер въезда», «Формы», «Источники», «Подписка», «Профиль».
- Верхний уровень продукта должен содержать только «Анализатор» и «Генерация».
- Dashboard, отчёт и сравнение используют статические данные из `apps/web/src/fixtures/demo.ts`.
- Кнопки feedback в `ReportWorkspace.tsx` не вызывают API.
- Анализ запускается не по байтам загруженного файла: endpoint `/analysis/runs` передаёт fake marker и `fixture_id`.
- Локальный запуск принудительно включает `fake_ocr`, `fake_llm`, fake storage, scanner, payment и KMS.
- Состояние документов, анализов, источников и форм хранится в памяти и пропадает после перезапуска.
- Каталог содержит только один кандидат МВД `needs_review` без официального raw PDF, hash и coordinate map. Заполняемых шаблонов нет.
- Если API не запущен, frontend молча показывает пустые формы вместо понятной ошибки соединения.
- Launcher использует Python 3.14, хотя README и проект заявляют Python 3.12.

   - valid_from/valid_to;
   - fetched_at/reviewed_at;
   - raw bytes;

   - media type;
   - source snapshot;

5. Если официальный original не найден или редакция не доказана:
   - не рисуй форму самостоятельно;
   - пометь «Требует проверки источника»;
   - оставь карточку видимой с понятным объяснением;

8. Не используй in-memory catalog.
9. Добавь source freshness scheduler и блокировку устаревших версий.
10. Карточка шаблона для пользователя:
   - нормальное русское название;

   - для чего;
   - статус;

   - редакция и дата проверки;

11. Не показывай пустую форму фильтров выше каталога. Сначала покажи карточки; поиск и фильтры сделай компактными.
12. Добавь редакторский bootstrap flow: официальный URL → безопасное получение → immutable snapshot → проверка реквизитов → ручное approve → публикация. Параметр `attempt_fetch` не должен только записывать лог без фактического получения.

Критерии приёмки:
- В генераторе видны восемь карточек с честными статусами.
- Каждая опубликованная государственная форма имеет реальный официальный raw и hash.

- Пункт 7 не превращается в выдуманный универсальный бланк.

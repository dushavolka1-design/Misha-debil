# ТЗ этапа 1: Анализатор документов РФ

Статус: проектирование MVP. Пользовательские функции **не реализуются** в этом этапе — только требования и границы.

Связанные артефакты: [glossary.md](glossary.md), [document-taxonomy.md](document-taxonomy.md), [acceptance-matrix.md](acceptance-matrix.md), [decision-log.md](decision-log.md), [../security/threat-model.md](../security/threat-model.md), [../adr/](../adr/).

Placeholders: `OWNER_LEGAL_NAME`, `OWNER_INN`, `OWNER_SUPPORT_CONTACT`, `TARIFF_*`, `RETENTION_*_NEEDS_REVIEW`, `JURISDICTION_POLICY_NEEDS_REVIEW`.

---

## 1. Цели

1. Дать физическим лицам в РФ инструмент для **структурированного разбора** договоров и пользовательских документов общего назначения: извлечение фактов, подсветка на неизменяемой PDF-подложке, сопоставление с утверждёнными source snapshots.
2. Поддержать сценарии: загрузка одного документа, сравнение нескольких, мастер въезда, заполнение формы, управление подпиской, удаление аккаунта.
3. Обеспечить разделение **fact / inference**, обязательные предупреждения и состояния неопределённости — без имитации юридической или медицинской экспертизы.
4. Заложить privacy-by-design: согласия по `consent_version`, retention, crypto-erasure, минимизация утечек через логи/кэш/telemetry.
5. Работать с российскими приватными AI/OCR через adapters (см. ADR-0002).

## 2. Явно исключённые цели (out of scope MVP)

| ID | Исключение |
|----|------------|
| X-01 | Юридическая экспертиза, правовое заключение, представление интересов в суде/госорганах |
| X-02 | Медицинская диагностика, заключение врача, разбор медицинских карт как клинический сервис |
| X-03 | Гарантия полноты/актуальности норм права «как у официального публикатора» |
| X-04 | Автоматическое подписание документов от имени пользователя |
| X-05 | Хранение «вечного» архива исходников без политики retention |
| X-06 | Публичный маркетплейс сторонних промптов/проверок без редакционного утверждения |
| X-07 | Обработка секретных/ДСП государственных документов как целевой сценарий |
| X-08 | Обещание конкретного нормативного срока ответа регулятору / удаления (`RETENTION_*_NEEDS_REVIEW`) |
| X-09 | Фиксация тарифов и реквизитов владельца в продукте (`TARIFF_*`, `OWNER_*`) |

**Жёсткое правило продукта:** AI и UI **не вправе** выдавать формулировки вида «заключение юриста/врача», «вам следует подписать», «это законно/незаконно» как итог без человеческой ответственности. Допустимы: facts, ограниченный inference с disclaimer, ссылка на source snapshot, статус `needs_review`.

## 3. Роли

| Роль | Возможности (MVP-контур) | Ограничения |
|------|--------------------------|-------------|
| **Гость** | Лендинг, описание продукта, регистрация/вход, публичные предупреждения | Нет загрузки документов, нет истории |
| **Пользователь** | Загрузка, анализ, сравнение, мастер въезда, формы, подписка, удаление аккаунта, экспорт своего отчёта | Нет доступа к чужим объектам (IDOR-защита), нет правки source registry |
| **Редактор источников** | Черновики source / form / check definitions, отправка на review | Публикация только после `review_status=approved` |
| **Юрист-рецензент** | Review отчётов/проверок по назначению, смена review status, комментарии | Не заменяет внешнюю юридическую услугу пользователю; scope — внутреннее качество |
| **Privacy officer** | Политики consent/retention, аудит согласий, эскалации утечек, запросы на erasure | Нет произвольного чтения содержимого документов без audit reason |
| **Support** | Тикеты, статус очереди, metadata аккаунта | Нет скачивания исходников без elevated break-glass + audit |
| **Admin** | RBAC, конфигурация adapters, feature flags, break-glass | Все действия аудируются; break-glass — `needs_review` по процедуре |

## 4. Сценарии

### 4.1. Загрузка одного документа — UC-UPLOAD-1

1. Пользователь принимает актуальные `consent_version` (если не приняты).
2. Загружает PDF/DOCX/JPEG/PNG в пределах SLO.
3. Система валидирует MIME/magic, антивирусный контур (`AV_PIPELINE_NEEDS_REVIEW`), кладёт оригинал в object storage отдельно от extracted text.
4. Ставит job в очередь OCR/анализа; пользователь видит статусы: `queued` → `processing` → `ready` | `failed` | `needs_review`.
5. Результат: facts + inferences + coordinate maps на immutable PDF underlay + обязательные предупреждения.
6. При low confidence / ambiguous — блоки UI `uncertainty`, без «уверенного» юридического вывода.

### 4.2. Сравнение нескольких документов — UC-COMPARE-N

1. Пользователь выбирает 2..`COMPARE_MAX_DOCS_NEEDS_REVIEW` документов своего аккаунта.
2. Система сопоставляет общие сущности (стороны, суммы, сроки, предмет) как facts и diff-inferences.
3. Отчёт явно маркирует: совпало / отличается / отсутствует в одном из документов / недостаточно данных.
4. Запрет: вывод «какой договор выгоднее юридически» как normative advice.

### 4.3. Мастер въезда — UC-ENTRY-WIZARD

1. Пользователь выбирает `form_version` мастера (approved).
2. Отвечает на шаги; опционально подтягивает facts из ранее загруженных документов с явным подтверждением.
3. На выходе — черновик заполненной формы + список недостающих полей + disclaimer, что это не официальная подача в госорган.
4. Актуальный перечень документов/оснований — только из source snapshots; gaps → `needs_review` / «уточните у компетентного органа».

### 4.4. Заполнение формы — UC-FORM-FILL

1. Выбор published `form_version`.
2. Автоподстановка кандидатов из facts с указанием provenance; пользователь подтверждает каждое критичное поле.
3. Экспорт/копирование по политике продукта; без автоматической отправки в внешние госсистемы в MVP (`GOV_SUBMIT_OUT_OF_SCOPE`).

### 4.5. Управление подпиской — UC-BILLING

1. Просмотр текущего плана (`TARIFF_PLAN_ID` placeholder), лимитов, статуса.
2. Смена/отмена через billing provider adapter (`BILLING_PROVIDER_NEEDS_REVIEW`).
3. Тарифные суммы и оферта владельца — **не** хардкодятся в этом ТЗ.

### 4.6. Удаление аккаунта — UC-ACCOUNT-DELETE

1. Пользователь инициирует удаление; подтверждение (step-up auth — `STEP_UP_AUTH_NEEDS_REVIEW`).
2. Останавливаются активные jobs; отзыв download links; постановка erasure workflow.
3. Crypto-erasure исходников и производных по ADR-0007; сохранение только legally required stubs (`LEGAL_HOLD_POLICY_NEEDS_REVIEW`).
4. Пользователь получает статус `deletion_requested` → `erasure_in_progress` → `erased` (или `partial_hold`).

## 5. Поддерживаемые входы

| Формат | Назначение | Примечания MVP |
|--------|------------|----------------|
| PDF | Основной контур договоров/сканов | Нормализация в immutable underlay |
| DOCX | Текстовые договоры/формы | Рендер/конвертация в PDF underlay pipeline |
| JPEG | Фото/сканы страниц | OCR обязателен |
| PNG | Фото/сканы страниц | OCR обязателен |

Неподдерживаемое в MVP: исполняемые контейнеры, произвольные архивы как вход анализа, паролированные файлы без явного UX (`ENCRYPTED_UPLOAD_POLICY_NEEDS_REVIEW`).

## 6. Пределы MVP по предметной области

**В scope:** договоры и пользовательские документы общего назначения (см. taxonomy): ДКП, аренда, услуги, НДА-like, трудовые шаблоны общего вида, бытовые заявления/анкеты, пользовательские PDF «просто прочитать и структурировать».

**Вне обещаний:** отраслевая due diligence, M&A, уголовный процесс, налоговая оптимизация, клинические решения, «гарантия соответствия 152-ФЗ / иным актам» как юридический вердикт.

Продукт позиционируется как **информационный помощник**, не как замена юриста/врача/нотариуса.

## 7. Функциональные требования (выборка ключевых)

| ID | Требование |
|----|------------|
| FR-01 | Раздельное хранение original object, extracted text, report artifacts |
| FR-02 | Каждый fact/inference имеет provenance и uncertainty state |
| FR-03 | UI всегда показывает disclaimer «не юридическая/медицинская экспертиза» на экранах анализа |
| FR-04 | Анализ нормативных ссылок только через approved source snapshots |
| FR-05 | RBAC по ролям §3; запрет IDOR на document/report/download |
| FR-06 | Одноразовые/TTL signed download URLs с audit |
| FR-07 | Очередь jobs с видимым статусом и идемпотентностью |
| FR-08 | Consent gate перед первой обработкой документа и перед сменой processors |
| FR-09 | Account deletion запускает erasure workflow |
| FR-10 | Редакторские артефакты публикуются только при `review_status=approved` |
| FR-11 | Coordinate maps согласованы с immutable PDF underlay |
| FR-12 | Запрет ответов модели в роли «я юрист/врач» (policy + тест) |
| FR-13 | Сравнение N документов с явным diff статусом по сущностям |
| FR-14 | Мастер въезда и формы версионируются (`form_version`) |
| FR-15 | Support/Admin break-glass только с reason code и audit |

## 9. SLO и бюджеты (черновик для MVP; числа — стартовые, часть на review)

| Метрика | Целевое значение MVP | Комментарий |
|---------|----------------------|-------------|
| Доступность API (месяц) | 99.5% | Исключая planned maintenance window `MAINT_WINDOW_NEEDS_REVIEW` |
| Макс. размер файла | 25 MiB | `MAX_UPLOAD_BYTES` |
| Макс. страниц / документ | 50 | `MAX_PAGES` |
| OCR p95 (≤10 стр., хороший скан) | ≤ 120 s | Иначе статус `processing` с ETA |
| Анализ p95 после OCR (1 док) | ≤ 90 s | Без внешнего human review |
| Очередь: max wait p95 | ≤ 5 min при номинальной нагрузке | При деградации — честный `queued` + отказ по backpressure policy |
| COMPARE_MAX_DOCS | 5 | `COMPARE_MAX_DOCS_NEEDS_REVIEW` |
| TTL signed download | ≤ 15 min | + revoke on delete |
| Retention originals | `RETENTION_ORIGINALS_NEEDS_REVIEW` | Не выдумывать срок |
| Retention reports | `RETENTION_REPORTS_NEEDS_REVIEW` | — |

Error budget: при исчерпании — freeze рискованных релизов (policy `ERROR_BUDGET_POLICY_NEEDS_REVIEW`).

## 10. Обязательные предупреждения и состояния неопределённости

### 10.1. Предупреждения (всегда / по событию)

- Глобальный disclaimer на анализе: сервис не оказывает юридическую/медицинскую услугу.
- Перед загрузкой: риск загрузки чужих/конфиденциальных документов; ответственность пользователя.
- При использовании AI/OCR adapters: данные уходят в processor согласно `consent_version`.
- При мастере въезда/формах: не является подачей в госорган.
- При low OCR quality: «текст распознан ненадёжно».

### 10.2. Состояния неопределённости (обязательная модель)

| State | Когда | UX |
|-------|-------|----|
| `ok` | Достаточная уверенность | Показ fact/inference с confidence |
| `low_confidence` | Ниже порога | Badge + не блокирует, но нельзя «сгладить» |
| `ambiguous` | Несколько конкурирующих чтений | Показать варианты, без автовыбора скрытно |
| `insufficient_data` | Нет основы для inference | Явный отказ от вывода |
| `needs_review` | Требуется человек | Блок «требует проверки», без normative advice |
| `failed` | Техсбой | Retry / support ref |

Запрещено: подменять `insufficient_data`/`needs_review` уверенным юридическим вердиктом.

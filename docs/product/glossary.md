# Глоссарий продукта «Анализатор документов РФ»

Статус: этап 1 (проектирование). Термины ниже обязательны для UI, API, отчётов и acceptance tests.

## fact

Утверждение, извлечённое из документа или утверждённого источника и представленное как наблюдаемое содержимое без оценки «правильно/неправильно» для пользователя.

- Примеры: дата договора, сумма, ФИО стороны, номер пункта.
- Обязательные поля: `value`, `provenance` (документ/источник + координаты/сегмент), `confidence`, `extraction_method`.
- Fact **не** является юридическим или медицинским заключением.
- Если извлечение неоднозначно — fact помечается `uncertainty_state=ambiguous|low_confidence` и требует явного предупреждения в UI.

## inference

Вывод системы поверх facts (сравнение, классификация риска, сопоставление с source snapshot, эвристика заполнения формы).

- Всегда отделяется от fact в API и UI.
- Обязательные поля: `basis_fact_ids[]`, `rule_or_model_id`, `confidence`, `disclaimer_key`.
- Inference **запрещено** формулировать как заключение юриста, врача или иного лицензируемого специалиста.
- При недостатке данных inference переходит в состояние `needs_review` или `insufficient_data`, а не «безопасный» ответ.

## source snapshot

Неизменяемый снимок нормативного/справочного материала на момент использования в анализе.

- Содержит: `source_id`, `version`, `content_hash`, `captured_at`, `approval_status`, `editor_id` (если применимо).
- Анализ ссылается только на утверждённые snapshots (`review_status=approved`), кроме явных режимов черновика для редактора источников.
- Отличается от «живой» страницы источника: URL может измениться, snapshot — нет.

## form version

Версионированный шаблон формы (мастера въезда, анкеты, заявления и т.п.).

- Идентификаторы: `form_id`, `form_version`, `schema_hash`, `published_at`, `review_status`.
- Заполненные ответы пользователя привязаны к конкретной `form_version`; смена версии не переписывает историю молча.
- Поля формы могут ссылаться на facts/inferences, но итоговое значение, отправленное пользователем, хранится как пользовательский ввод.

## consent version

Версионированный текст согласия (обработка ПДн, особые категории, передача в AI/OCR-adapters и т.д.).

- Идентификаторы: `consent_id`, `consent_version`, `locale`, `effective_from`, `content_hash`.
- Действительное согласие = запись `user_id` + `consent_version` + `accepted_at` + evidence (IP/device fingerprint policy — `needs_review`).
- Смена политики требует новой `consent_version`; старые принятия не переинтерпретируются автоматически.

## review status

Статус редакционной/комплаенс-проверки артефакта (источник, form version, consent version, специализированная проверка, отчёт юриста-рецензента).

Допустимые значения MVP:

| Значение | Смысл |
|----------|--------|
| `draft` | Черновик, не для пользовательского анализа |
| `in_review` | На проверке |
| `needs_review` | Требует решения человека; авто-публикация запрещена |
| `approved` | Утверждено к использованию в продуктовых потоках |
| `rejected` | Отклонено |
| `retired` | Выведено из употребления; исторические ссылки сохраняются |

Правило: пользовательские сценарии анализа используют только `approved` (и `retired` только для исторического просмотра уже созданных отчётов).

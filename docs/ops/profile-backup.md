# Полный backup профиля — модуль, не готовое обновление

Дата: 2026-09-06. Статус: отдельный реализованный модуль; Windows CI проверяется отдельно. Не объявляет готовность Docly 0.2.2.

`app.profile_backup.create_profile_backup(profile, backup_root, program_dir=...)` требует предварительной остановки всех писателей профиля. Установщик пока его НЕ вызывает. При любом исключении вызывающий код обязан прекратить обновление до изменения программы или данных.

Результат: отдельный неизменяемый по соглашению каталог `profile-<uuid>` вне дерева программы и профиля. В `profile/` сохраняются все обычные файлы и пустые каталоги, включая исходные DB/WAL/SHM, документы, вложения, настройки и пользовательские шаблоны. `manifest.json` содержит размеры и SHA-256 всех файлов. Это контроль целостности, НЕ цифровая подпись и НЕ защита от злоумышленника, переписывающего одновременно файлы и manifest.

В `sqlite/` находятся отдельные самодостаточные SQLite-образы. Они создаются SQLite backup API из проверенной временной копии DB/WAL. Оригинальная база не открывается: даже чтение SQLite способно менять SHM read marks. Для каждого образа выполняется integrity_check. Исходные WAL/SHM нельзя накладывать поверх согласованного образа при будущем восстановлении.

При ошибке, нехватке места, изменении исходного дерева, испорченной базе или timeout незавершённый snapshot не публикуется. Успешные копии не перезаписываются и автоматически не удаляются. Ссылки/junction/reparse points и специальные файлы отклоняются. Требуются обычное локальное дерево и надлежащие ACL каталога backup. Снимок не зашифрован; не загружайте реальные backups в GitHub или CI artifacts.

Локальные проверки: 16 unittest-сценариев прошли на Linux/Python 3.13. Windows/Python 3.12 проверяет отдельный workflow `docly-profile-backup.yml`; его результат нельзя заменять локальным успехом.

```bash
PYTHONPATH=apps/api python -m unittest discover -s apps/api/tests -p test_desktop_profile_backup.py -v
```

Остаются обязательными: wiring в pre-install после подтверждённой остановки Docly; резервирование прежней программы; идемпотентный транзакционный rollback; restart старой версии; настоящий установщик 0.2.0 → 0.2.2; PostgreSQL migration acceptance. Модуль сам по себе ни один из этих installer gates не закрывает.

# Установщик Docly для Windows x64

## Важное отличие от исходного задания
Проверенный `master` (`7ab48303efa92b2e52702256dcdd360c9540d273`) использует desktop-профиль SQLite и файловое хранилище. Существующий launcher прямо исключает PostgreSQL/Redis и использует `migrate_sqlite`, а не Alembic. Установщик сохраняет этот режим. API, UI, анализ документов и схема базы не изменяются.

## Сборка
На Windows x64 нужны Git, Node.js 20+, pnpm 9.15.9 и Inno Setup 6.3+ (https://jrsoftware.org/isdl.php).

```powershell
git switch chore/docly-fast-windows-installer
pnpm installer:windows
# Без предварительной установки pnpm:
powershell -NoProfile -ExecutionPolicy Bypass -File installer/build-installer.ps1
```

Результат: `release/Docly-Setup-x64.exe`. Рядом создаются `build-info.json` (размер в байтах, SHA256, исходный коммит), файл SHA256 и `payload-manifest.txt`.
Сборка берёт только отслеживаемые Git файлы по разрешённым путям. Перед локальной сборкой добавьте новые installer-файлы в Git. `.git`, зависимости, venv, кэши, реальные `.env`, логи, пользовательские базы, временные файлы и приватные ключи исключаются. Это не универсальная гарантия обнаружения всех возможных секретов: исходники также должны проходить проверку перед релизом.

## Установка и первый запуск
- Windows 10/11 x64; установка для текущего пользователя в `%LOCALAPPDATA%\Programs\Docly`, без административных прав для самого Docly.
- Ярлыки «Docly» на рабочем столе и в меню «Пуск»; штатная запись и деинсталлятор в установленных программах.
- Проверяются Windows, PowerShell, Node.js 20+ x64 и Python 3.12+ x64. Рекомендуется Python 3.12 для совместимости существующих зависимостей.
- Если Node/Python нет, предлагается winget; при отсутствии winget открывается официальный сайт. При ошибке установка не продолжается. Установщик зависимостей может отдельно запросить повышение прав. В тихом режиме зависимости не устанавливаются автоматически: проверка завершается ненулевым кодом.
- Первый запуск ярлыка показывает PowerShell с прогрессом установки зависимостей. Загружаются pnpm 9.15.9 (локально, без `corepack enable` и без глобального npm), JS-зависимости из lockfile, Python-пакеты из существующих requirements и локальный `py_dar`. Собирается production Next.js. Существующий скрипт проверяет/загружает Noto Sans по SHA256 из манифеста. Нужен интернет и несколько минут.
- `.env` создаётся только на компьютере пользователя из `.env.example`: локальные настройки, `ALLOW_FAKE_PROVIDERS=true`, случайный SESSION_SECRET (32 криптографически случайных байта). Существующий `.env` не перезаписывается, секрет не включается в EXE.
- После подготовки wrapper вызывает неизменённый `scripts/windows/start-dar-silent.vbs` → `docly_launcher.py`. Launcher создаёт SQLite, ждёт `/live` и `/ready` и открывает `/app/analyzer`. Предпочтительные порты 8000/3000; существующий launcher выбирает другие, если занято.
- PostgreSQL, Redis, Docker, Electron и Tauri не требуются и не устанавливаются.
- Журнал подготовки: `artifacts\local-run\installer-bootstrap.log` внутри установки. При ошибке можно повторно запустить ярлык.

## Повторная установка и удаление
Установка/удаление блокируются, если найдены работающие процессы из папки Docly. Закрытие браузера не останавливает фоновые API/Web. На первой версии остановите соответствующие процессы Python/Node Docly в Диспетчере задач (проверьте путь/командную строку; не завершайте посторонние процессы).

Удаление: Параметры Windows → Приложения → Docly → Удалить. Удаляются поставленные файлы, ярлыки, запись и известные каталоги установленных зависимостей. Пользовательские данные `%LOCALAPPDATA%\Docly\data`, локальный `.env` и диагностические логи сохраняются. Поэтому папка установки может остаться. Это намеренная защита данных; корневая папка рекурсивно не удаляется.

## Проверки и релиз
GitHub Actions `Docly Windows installer` собирает EXE на `windows-2022` и запускает `installer/smoke-test.ps1`: чистая установка в стандартную папку, оба ярлыка/регистрация, отсутствие секретного окружения/готовых зависимостей в payload, полный первый запуск, SQLite, HTTP 200 `/live`, `/ready`, `/app/analyzer`, повторный запуск без дубликатов, сохранение `.env` и данных при переустановке, штатный деинсталлятор, сохранение пользовательских данных. Тест предназначен ТОЛЬКО для одноразового Windows CI runner; не запускайте его на рабочем компьютере с существующим Docly.

EXE и диагностические результаты сохраняются в артефактах даже при неуспешном smoke; такой EXE НЕ считается рабочим релизом. Предварительный GitHub Release создаётся только после успешного smoke. Фактические результаты: `installer/CI-RESULT.md` и соответствующий запуск Actions. `installer/STATUS.md` — конспект продолжения работы.

До стабильного релиза вручную проверить на Windows 10 и 11: графическую установку, запуск двойным щелчком ярлыков и открытие браузера, отсутствие Node/Python и отказ от установки, согласие на winget, отсутствие winget, прерывание загрузки, повторный запуск после перезагрузки, отказ при занятых файлах, удаление через Параметры. CI на Windows Server не подменяет эти проверки. Проверки PostgreSQL/Redis/Alembic неприменимы к сохранённому launcher.

## Ограничения первой версии
Не автономный offline-дистрибутив. Нет подписи кода/автообновления; Windows SmartScreen может предупреждать. Python requirements остаются исходными диапазонами версий, поэтому будущие установки не полностью воспроизводимы. Производительность зависит от машины и сети. Нельзя утверждать, что мастер-ветка продукта или полный монорепозиторий проверены: эта задача касается только installer/launcher. Статус готовности определяется реальными результатами CI, а не наличием конфигурации сборки.
